# Physical test log - microSD module (bench `s` command)

Tester: Nicolás (wiring). Entries written by Claude from the chat and the serial output.
Module: blue 6-pin microSD adapter (CS, SCK, MOSI, MISO, VCC, GND) with a 14-pin chip that looks like a 74LVC125A
level shifter and a SOT-223 regulator marked 1117 (read from a photo, not confirmed). Powered from VIN (5 V pin).
Pins used (proposed in `include/board_pins.h`, not verified before this test): SCK GPIO18, MISO GPIO16 (`RX2`),
MOSI GPIO17 (`TX2`), CS GPIO4. The tester reported the module as installed; the card has files on it.

## Result of `s` (read-only probe, 4 MHz)

```
SD: SCK=18 MISO=16 MOSI=17 CS=4, 4 MHz
sdcard_mount(): f_mount failed: (13) There is no valid FAT volume
SD: mount failed (no card, wiring, power, or the card is not FAT16/FAT32)
```

Reading (inference from the library's message, not a direct measurement): FatFs error 13 comes from the mount step,
after the card has been initialised, so the wiring and power most likely work and the card answered. The card does not
carry a FAT16/FAT32 volume the library can mount; it is probably exFAT (typical for cards above 32 GB) or another file
system. Card capacity and current format were not read. Not yet tested: reading files.

## Format from the ESP32 (tester's explicit consent: erase everything, 16 GB card)

Command `sdformat ERASE-ALL` (bench; formats only when the mount fails with FatFs error 13, using the library's
`format_if_empty`, FM_ANY). Output:

```
sdcard_mount(): f_mount failed: (13) There is no valid FAT volume
SD: card type SDHC/SDXC, size 14992 MB
  (root folder is empty)
```

The card mounted after the format and the root folder is empty: **SPI wiring, power from VIN and the pin choice work**
(the card accepted a format, i.e. writes), the data that was on it is gone. The file system created was chosen by the
library (FM_ANY, expected FAT32 for 14.6 GiB; the type was not printed). Not yet tested: writing and reading back a file,
repeated mounts after a reset, behaviour while the emitter transmits.

## Serial upload of an IRDB file (`tools/irdb_upload.py` + bench `sdput` / `sdcrc` / `sdls`)

`irdb_LG.ir` (574 bytes, Flipper-IRDB, CC0): uploaded in 256-byte chunks, written to a temp name, renamed after the
CRC32 matched. After an EN-pin reset (the card was unmounted and mounted again): `sdls /irdb` lists the file with 574
bytes and `sdcrc` returns **299F5B22**, equal to the CRC32 computed on the PC. So write, rename, remount and read-back
work for this one small file. Not tested: large files (limit 64 KB by design), many files in a row, a full card,
power loss during a write (the temp-file-then-rename design is meant to cover it, untested), card removal.
